# Figure Gallery 产品需求文档

## 1. 文档状态、产品目标与定位

- 状态：Product blueprint，作为第一阶段产品范围的权威说明；
- 技术边界：已接受 Payload CMS + Next.js、PostgreSQL 16 与 S3 兼容对象存储；PR-00/PR-01 已建立正式工程与核心目录，后续正式路线暂停；
- 实施边界：本文件不授权开始 PR-02、复制 `spikes/` 或 personal gallery、部署或访问未获授权的外部站点。

**PRD-001 — 精确定位。** Figure Gallery 是一个以角色为入口、以独立 `FigurePrototype` 造型为核心实体的二次元拍摄姿势数据库。系统尽可能自动发现某角色已有的正版手办、静态完成品和景品，再通过来源证据、候选处理、人工正式确认和公开只读图库，把完整手办数据库转化为“一种造型一张封面、详情保留全部角度”的拍摄参考能力。

第一阶段不是通用手办社区，也不是商品交易平台；产品只服务于管理员维护资料和公开访客按角色浏览 Cos 动作参考图这两类核心用途。

**PRD-002 — 收录边界。** 第一阶段收录有可核验正式授权的比例手办和景品，包括已发售、预售、未发售、完整灰模，以及正式授权第三方厂商产品；不收录未授权 GK、同人自制、盗版、黏土人、可动人偶、盲盒等首阶段范围外类型。授权或分类不确定时只能保留候选并等待人工判断。

**PRD-003 — 原型与版本。** 不同厂商或不同造型原型即使动作相似也分别建档；同一原型的普通版、豪华版、再版、特典版和纯异色版归入同一 `FigurePrototype`，以多个 `FigureVersion` 表达，不在公开图库重复出卡。

**PRD-004 — 不可变业务原则。** 候选数据不得直接创建、覆盖或删除正式数据；正式变化必须由有权人工确认并写入审计；现有正式主图不得被采集、重采集、来源失效、候选删除或后台通用保存自动替换。

**PRD-005 — 发现与权威分离。** Hpoi 是 discovery/coverage benchmark，不是事实或图片权威。系统可在明确授权的隔离流程中读取第三方公开搜索索引返回的 Hpoi URL/标题/摘要文本，但 Hpoi direct request 必须为 0；正式商品事实和图片只能来自受审的非 Hpoi 来源。`ProductRecord` 是来源级过渡记录，不等于最终 `FigurePrototype`，不得自动 merge。

## 2. 用户与核心场景

| 用户/系统身份 | 主要目标 | 第一阶段权限边界 |
| --- | --- | --- |
| 匿名公开访客（主要为 Coser） | 按角色快速找到不同正版手办原型的姿态参考 | 只读公开搜索、消歧、分页图库和灯箱；无账号、无下载、无详情修改能力 |
| Admin | 承担候选审核、目录维护、主图选择、领域操作、设置和运维场景 | 首版只有一个 Admin 角色，但可有多个独立同角色账号；每个动作仍受 allowed target、owner、状态机、事务、乐观锁和审计约束 |
| 候选客户端 | 以离线文件或经明确授权的来源提交候选元数据与文件 | 每客户端独立凭据和 owner；只可写自己的候选聚合，不能写正式数据 |

核心场景：访客输入角色标准名、译名或别名；唯一匹配时直达角色图库，同名时按作品消歧。Admin 在人工录入职责中把允许使用的资料放入候选池，在审核职责中逐字段接受/拒绝、选择或新建正式目标、归入版本、人工选主图并说明理由；同一 Admin 角色的独立账号可在审计和并发保护下合并、拆分并按 operation ID 撤销指定操作，也可在运维职责中导出开放格式并将 PostgreSQL 与对象 manifest 作为同一快照恢复。

## 3. 第一阶段范围

### 3.1 必须交付

1. 核心目录：作品、角色及中日英名/别名、厂商及状态、手办原型、版本；
2. 来源和候选池：人工录入/粘贴 URL、明确允许的离线导入、受限候选客户端、幂等来源身份、候选字段与多张候选图；
3. 审核：工作项、允许目标、逐字段接受/拒绝、理由、完成/重新打开、人工正式目标和版本归属；
4. 媒体：原图、缩略图、预览图、SHA-256、感知哈希、稳定 `storageKey`、人工提升和主图保护；
5. 正式操作：隐藏/恢复、来源失效、merge、split、按 operation ID 指定 undo、并发冲突和完整审计；
6. 公开图库：极简角色搜索、唯一直达、同名作品消歧、分页、4/3/2 列、原比例图片、当前页灯箱、成人图片设置；
7. 可迁移性与恢复：JSON、多表 CSV、媒体 manifest、PostgreSQL 备份、S3 对象清单、联合恢复与完整性审计。

### 3.2 明确不包含（非范围）

- 用户注册、登录、评论、收藏、投稿、关注、社交或个性化推荐；
- 交易、价格、库存、购买链接聚合、发售提醒或商业结算；
- 前台手办详情页、版本卡片、下载按钮、原图批量导出或独立第三方/开发者下载 API；前端所需的公开只读接口保留；
- 点赞、TTS、自动视频生成、AI 图片生成、自动主图选择、自动授权判断、自动实体合并或相似图自动删除；
- 原画图库、真人 Cos 图库或其他内容产品；
- Hpoi direct crawler/scrape/API/图片/浏览器自动化，厂商/会员购的未授权自动采集，登录采集、Cookie、验证码规避或定时抓取；第三方公开搜索索引的 Hpoi candidate discovery 不属于 direct Hpoi access，但仍不能提供正式事实或图片；
- 生产云部署、真实域名、商业监控或跨区灾备采购。

### 3.3 未来预留但不承诺

经独立需求、许可与安全评审后，可考虑：原画独立图库、姿势分类、发售日期分组、厂商分组、多管理员角色、定时采集、正式授权 Source Adapter、相似图搜索、AI 重复提示和内容审核协作。预留不得提前扩大第一阶段 schema、权限或前台入口。

## 4. 功能需求

### 4.1 核心目录

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| CAT-001 | `Work` 保存稳定 ID、名称、别名和状态 | 同名角色可通过作品关系消歧；软删除不破坏历史关系 |
| CAT-002 | `Character` 支持可选作品、中日英名称与多个别名 | 标准名和别名均可搜索；多人原型可关联多个角色 |
| CAT-003 | `Manufacturer` 保存名称、别名、授权核验状态和 active/hidden 状态 | 未确认或禁用厂商不能使原型自动发布 |
| CAT-004 | `FigurePrototype` 表达作品、多个角色、厂商、类型、比例、发布/隐藏/成人/软删除状态和人工主图 | 不同厂商/原型独立；无合格人工主图不得公开 |
| CAT-005 | `FigureVersion` 归属于一个原型，表达版本名、再版/特典/异色等版本差异 | 版本不生成独立公开图库卡片；变更保持审计 |

### 4.2 来源与候选池

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| CAND-001 | 第一阶段只接受人工录入、人工粘贴 URL、明确允许的离线文件或未来单独授权的 adapter；会员购和厂商官网只作人工补充/核验来源 | 粘贴 URL 只保存为文本，不触发服务端抓取；Hpoi、会员购和厂商官网均不自动访问 |
| CAND-002 | 每个 CandidateClient 具有独立、可归因凭据和 active/disabled/revoked 状态 | 服务端只保存 token hash；创建或轮换生成的新明文只在该次响应显示一次；disabled 可恢复，revoked 不可逆 |
| CAND-003 | 来源优先以 `(sourceType, sourceItemId)` 全局唯一；无稳定 ID 时才使用规范 URL fallback | fallback 获得稳定 ID 后可迁移且不重复；SourceRecord 只保存首次发现归因且不提供 client 直接 CRUD，各 client 的 Candidate owner 继续隔离 |
| CAND-004 | candidate upsert 与 multipart 文件上传必须支持客户端候选 ID、幂等键和重试 | 同请求重复执行返回同一身份；同 URL 内容变化形成明确新内容或差异 |
| CAND-005 | 候选保存原始字段、来源快照摘要、采集/录入时间、匹配和审核状态及字段差异 | 重采集只产生候选差异，不改正式字段或主图 |
| CAND-006 | 候选客户端没有 Character、Manufacturer、Prototype、Version、Setting、发布或主图写方法 | REST/GraphQL/Local API/Admin/custom endpoint 绕过均被拒绝 |

### 4.2A 发现与覆盖方向

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| DISC-001 | 从角色 aliases、作品名和产品类别生成确定性、有限的 `site:hpoi.net` 搜索矩阵 | 每角色最多 30 query、每 query 最多 10 result、原始结果最多 200；相同 URL 幂等 |
| DISC-002 | 搜索 provider 只返回索引 URL、标题、摘要、查询和排名；应用不得请求这些 Hpoi URL | `hpoiDirectHttpRequests`、`hpoiDirectBrowserNavigations`、`hpoiScrapeRequests`、`hpoiApiRequests` 全部为 0 |
| DISC-003 | `DiscoveryCandidate` 自动判断角色/作品/首期类型，不能确定时保留 `ambiguous` | 小柴郡与柴郡、Ram 与 Rem 分离；黏土/可动/GK 等明确非范围项可标为 out_of_scope |
| DISC-004 | 候选先匹配已有 ProductRecord；新目标用标题、厂商、角色和作品生成定向 official resolution 查询 | 成功来源必须在受审非 Hpoi allowlist；未解决项保持原因，不造数据 |
| DISC-005 | 本地 coverage 显示候选、范围、已有、新目标、解析、收录和未解决指标 | 明示“相对于本次搜索索引候选集”；第二轮 candidate/product/SHA-256 对象均幂等 |
| DISC-006 | `prototypeHint` 只提供疑似同造型提示 | 不使用 pHash，不自动 merge，不写正式 Payload |

### 4.3 审核工作流

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| REV-001 | `ReviewWorkItem` 记录候选、允许目标、审核人、状态、lock version、开始/完成时间和原因 | 每次审核只能作用于 allowed targets，或经明确动作新建正式原型 |
| REV-002 | 审核员可预览全部候选图，对允许字段逐项接受或拒绝，并保存原因 | 至少验证接受一项、拒绝一项、选择目标/版本和保存理由 |
| REV-003 | 支持 defer、ignore、complete；完成后普通入口不可继续改写 | reopen 必须是明确动作并新增审计记录 |
| REV-004 | 创建正式原型、归入版本、选择主图与完成工作项必须处于定义清楚的原子事务/补偿边界 | 失败时不留下半成品正式记录或虚假成功日志 |
| REV-005 | 两名管理员同时修改同一工作项时，后提交者得到明确版本冲突 | 不静默覆盖；业务状态与日志一致 |
| REV-006 | 最小 Admin 审核视图支持键盘完成关键动作并显示可恢复错误 | 自动浏览器测试覆盖完整流程、错误恢复和权限失败 |

### 4.4 媒体与主图

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| MED-001 | 服务端从实际字节验证 magic bytes、MIME、格式、大小和像素尺寸，并计算 SHA-256 与 aHash | 非图片、超限、声明/内容不符和解码失败均被拒绝 |
| MED-002 | SHA-256 是内容身份；aHash 只作相似性提示 | 同字节换文件名/URL不重复存储；同 URL 不同字节形成新内容 |
| MED-003 | 原图与 thumbnail/preview 使用稳定 `storageKey` 存于 S3 兼容边界 | 公开 URL/endpoint/prefix 变化不改变业务引用；派生图可重建 |
| MED-004 | 候选媒体只有经人工 promote 后才能成为正式媒体，主图只能由有权人工选择 | 候选客户端和自动任务不能设置或替换主图 |
| MED-005 | 来源失效/删除、候选软删或重新录入不得删除已引用正式主图 | 正式原图和引用保持；清理由引用检查和延迟策略控制 |
| MED-006 | missing/orphan 审计默认只报告，不自动删除；上传失败执行可重试补偿 | S3 中断不产生正式记录、主图变化或成功 OperationLog |

### 4.5 正式数据与领域操作

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| OPS-001 | 所有正式变化必须调用领域 service，并在数据库事务、乐观锁和 `OperationLog` 下执行 | generic Admin/REST/GraphQL/Local API 不能直接保存正式变化 |
| OPS-002 | merge 按明确作用域迁移关系并保留可追溯的被合并记录 | operation UUID、before/after、scope、version 和依赖完整 |
| OPS-003 | split 只移动明确选择且保持闭包的关系 | 不产生断裂来源、版本、候选、媒体或主图关系 |
| OPS-004 | undo 必须指定 operation ID，且只撤销仍安全的操作 | 无关作用域可分别撤销；存在后续依赖时明确拒绝或使用有测试的级联策略 |
| OPS-005 | 正式条目支持受审计隐藏/恢复，SourceRecord 支持失效状态 | 隐藏不等于删除；恢复保持主图、版本和日志 |
| OPS-006 | `SystemSetting` 至少包含 `publicReadEnabled`、`showAdultImages`、`galleryPageSize=16`、`candidateUploadSizeLimit` 与 `allowedImageFormats` | 修改仅限 Admin 的受控动作，写审计并使服务端读取、分页和上传策略生效 |

### 4.6 公开搜索与图库

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| PUB-001 | 首页是以角色查询为唯一主任务的极简搜索页 | 无内容详情、推荐流或账号入口干扰主任务 |
| PUB-002 | 搜索标准名、中日英名和别名，支持规范化后的精确与部分匹配 | 唯一匹配直接跳转；无结果给出清晰空状态 |
| PUB-003 | 多个同名角色必须按作品消歧 | 每个选项同时显示角色名和作品；不得猜测自动跳转 |
| PUB-004 | 角色页顶部显示大标题角色名，只展示 published、未隐藏且有人工主图的原型 | 多角色原型在各关联角色可发现并显示轻量多人标记；版本不重复出卡 |
| PUB-005 | 每页默认 16 个原型，默认按正式记录创建时间稳定排序，并具有可验证页边界 | 17 条形成 16+1；越界页不重复、不漏项 |
| PUB-006 | 桌面、平板、手机分别为 4/3/2 列，图片保持原始宽高比且不裁切 | 代表 viewport 的 computed style 和固有尺寸通过浏览器测试 |
| PUB-007 | 点击图片只提供放大/缩放、关闭和当前分页内上一张/下一张 | 支持 Esc/键盘；首尾边界明确，不跨页预取导航 |
| PUB-008 | 成人图片默认由服务端隐藏，只有授权管理员打开设置后才可公开显示 | 缓存键包含设置状态；客户端参数不能绕过过滤 |
| PUB-009 | 前台不显示手办数量、手办详情、版本资料或下载按钮 | HTML、可访问名称和网络响应均不暴露下载动作或候选/私有字段 |

### 4.7 导出、备份与恢复

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| DATA-001 | 导出可解析、带 schema version 的 JSON 与多表 CSV | 覆盖正式/候选关系、ReviewWorkItem、OperationLog、SystemSetting，不含图片字节和明文凭据 |
| DATA-002 | 媒体 manifest 记录关系 ID、storageKey、SHA-256、aHash、尺寸、格式和对象状态 | 可逐项验证且不依赖公开 URL |
| DATA-003 | PostgreSQL dump 与对象 manifest 共享 snapshot ID | 空数据库/空 bucket 恢复后计数、关系、主图、来源状态、成人设置一致 |
| DATA-004 | 恢复后必须重跑权限、领域、媒体、公开读取和 missing/orphan 合同 | 原始备份、图片对象或秘密不得进入 Git/普通 CI Artifact |

| NFR-008 | 可观测性 | 请求、审核、领域操作、上传和恢复具有结构化 trace/operation ID；日志秘密扫描为 0 命中 |
| NFR-009 | 可迁移性与锁定控制 | PostgreSQL 标准备份、开放 JSON/CSV 与对象 manifest 可独立解析；业务引用不依赖 Payload URL 或公开媒体 URL |
| NFR-010 | 发布质量 | lock install、typecheck、lint、unit/integration/contract/browser/attack/migration/restore/build/standalone 和仓库卫生检查全部通过后才可推进 |

## 6. 第一阶段成功标准

在功能验收之外，以以下指标判断首阶段是否达到可发布质量；未取得测量数据时标为“未验证”，不得写成达成：

1. 核心验收 fixture 中，标准名/别名搜索、唯一跳转、同名消歧、多人关联和版本去重正确率 100%；
2. 4/3/2、16+1 分页、原比例、灯箱首尾、成人开关、无详情/无下载浏览器场景 100% 通过；
3. 候选重复提交和文件内容去重场景 100% 幂等，候选越权与正式写入攻击 100% 被拒绝；
4. 正式字段和主图的自动覆盖次数为 0；正式主图因来源/候选变化丢失次数为 0；
5. 每次正式变化的 OperationLog 覆盖率 100%，并发静默覆盖为 0，关系断裂为 0；
6. 恢复前后业务计数、关系 digest、正式主图、来源状态和成人设置差异为 0；对象缺失/孤儿均被报告；
7. 内部试用中，审核员处理一个含 3 张候选图和 3 个候选字段的标准工作项，中位完成时间目标不高于 3 分钟；该指标用于优化，不得以降低安全或审计步骤达成；
8. 未授权外部自动请求、Hpoi direct 请求、提交秘密、真实生产数据和未审计正式写入均为 0；索引候选数与 Hpoi direct 四项计数分开报告。

## 7. 总体验收与停止条件

- 每项需求必须在 [需求追踪矩阵](TRACEABILITY_MATRIX.md) 映射到实体/服务、API 或 UI、交付 PR、测试和风险；
- 实施严格遵循 [PR-00—PR-08 交付路线](DELIVERY_ROADMAP.md)，一个 PR 达到停止条件后不得自动开始下一项；
- 正式项目从官方脚手架干净初始化，研究与 spike 不作为运行时输入；
- Hpoi direct automation 保持网络硬禁令；第三方公开搜索索引只提供 discovery/coverage 文本信号，具体见 [产品北极星](PROJECT_NORTH_STAR.md)与[安全边界](SECURITY_BOUNDARIES.md)；
- 本蓝图完成后停止：不初始化应用、不部署、不导入真实图片、不开始原画图库。
