# Hpoi 真实传输门禁（VAL-01B）

## 结论

- **门禁结论：未通过。**
- **Hpoi 可行性评级：低**（针对自动候选采集；人工浏览价值不在此评级内）。
- **推荐定位：仅人工参考。** 在取得 Hpoi 事先明确书面许可并重新执行剩余门禁前，不把 Hpoi 用作自动发现索引或自动数据源。

纯技术上，Python `requests` 直连取得了 3 个固定商品页和 3 个固定角色页的真实公开 HTML，修正后的候选探测器也能解析 3 个商品页。但公开用户协议的 3.10 条对机器人、蜘蛛、爬虫及其他自动程序/脚本获取平台服务、内容或数据提出了事先明确书面许可要求。该公开规则出现后，本轮按任务停止条件立即停止，没有继续使用临时代理，也没有请求图片。

这只是项目的操作门禁结论，不是法律意见；`robots.txt` 中没有路径规则也不能抵消公开协议文本或被解释为授权。

## 解析器兼容性

真实页面与 VAL-01 手工夹具有两个关键差异：

1. 当前字段使用 `.hpoi-infoList-item` 内的 `span`/`p`，不是夹具的 `dt`/`dd`；
2. JSON-LD Product 嵌套在 WebPage 的 `mainEntity`，且同一树中先出现 CreativeWork。

探测器已做通用修正：识别两种字段结构、优先遍历嵌套 Product、保留标题兜底，并仅接纳 Hpoi 的 `/gk/cover/` 与 `/gk/pic/` 媒体路径，排除 favicon、样式资源和 loading 图。没有硬编码商品标题或 ID。

修正后 3 个真实商品页均解析出数字 ID、名称、角色、作品、制作、属性和比例；其中 2 个还解析出当前出货日。对缓存的 `80002` 连续运行两次，第一次为 `new`，第二次为 `unchanged`。字段摘要见 [`evidence/hpoi-real-html-parser-summary.json`](evidence/hpoi-real-html-parser-summary.json)。

仍有一个重要限制：`/gk/pic/` 同时可能包含官图和用户图。当前 spike 能发现候选媒体 URL，但不能证明每个 URL 都是官方商品图；正式系统不得据此自动发布或选主图。

## 公开图片验证

**没有发起图片 HTTP 请求，成功取得图片字节数为 0。**

在读取公开协议前，商品 HTML 已经暴露封面和缩略图 URL；但协议请求是第 14 次请求，内容触发强制停止条件。因此没有执行无 Referer/正常商品页 Referer 对照，也没有执行临时代理图片对照。

以下项目均未执行，不能报告为失败或通过：

- 图片最终 URL 与重定向链；
- 图片 Content-Type、真实格式、尺寸；
- SHA-256 与 aHash；
- 不同 URL 的内容去重；
- 403 或基础 Referer 校验信号；
- 来源删除后的本地保留验证。

仓库没有提交任何 Hpoi 图片，临时目录中的响应也只有 HTML/文本。

## robots 与公开规则

`robots.txt` 返回 13 字节，内容只有 `User-Agent: *`，没有 `Allow` 或 `Disallow`。因此它没有对固定样本路径提供可用的技术信号；这不表示允许自动访问。

商品页页脚公开链接到 `/protocol`。该用户协议返回 200，标题为“用户协议”，其 3.10 条对未事先取得明确书面许可而使用机器人、蜘蛛、爬虫或其他自动程序/脚本获取平台服务、内容或数据作出限制。观察到该事实后，本轮立即停止所有 Hpoi 请求。小型摘要见 [`evidence/hpoi-public-rules-summary.json`](evidence/hpoi-public-rules-summary.json)。

正式采集前仍须由项目所有者人工确认最新边界并取得、保存 Hpoi 的书面许可；不能从 robots 的空白规则反推许可。

## 安全边界执行情况

- 无登录、Cookie、Token、账号或浏览器会话；
- 固定 User-Agent，不轮换请求头；
- 单并发、至少 2 秒间隔，实际 14/30 次；
- 没有自动重试、没有重定向跳转、没有猜测 API 或扩大样本；
- 没有绕过 TLS 校验、403、验证码、登录或 App；
- 代理只做监听检查，未用于 Hpoi HTTP；
- 没有永久代理、Clash、注册表或系统网络修改；
- 完整响应只在系统临时目录，仓库仅保存小型脱敏夹具和摘要；
- 没有图片、凭据、代理配置或完整页面进入 Git。

## 下一步建议

1. 当前停止 Hpoi 自动请求，把 Hpoi 仅作为人工浏览参考。
2. 若仍希望把 Hpoi 作为自动发现索引，由项目所有者先取得可核验的事先书面许可，并记录允许的路径、频率、图片范围和保留方式。
3. 只有完成第 2 步后，另开独立任务继续未执行的代理 HTML、两商品公开缩略图、Referer、哈希与内容去重门禁；不得沿用本轮剩余 16 次额度自行继续。
4. 未取得许可时，发现与核验应优先使用明确允许的厂商官网、会员购或其他公开官方来源，并继续只写候选池。
5. VAL-02 如获单独授权，应只使用合成数据和本轮已提交的脱敏夹具，不进行 Hpoi 实时采集。
